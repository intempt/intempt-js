Consent and opt-out

These are two different mechanisms and mixing them up is the most common integration mistake with this SDK.

optOut() / optIn()consent()
What it doesTurns collection off and onSends an event recording the visitor's decision
Stops tracking?YesNo
Survives reload?Yes — localStorageIt is an event, not state
ScopeThis origin only—

So a "reject" flow needs both: consent({ action: 'reject' }) to record the decision, then optOut() to stop collecting.

The ordering trap

consent() is itself gated on the opt-out flag. Calling optOut() first makes the following consent() a silent no-op — no error, no event, no audit record of the refusal. Record first, then opt out. The reverse applies on re-consent: optIn() before consent({ action: 'accept' }), or the acceptance is never recorded.

One limitation to plan around: the opt-out flag lives in localStorage, which is origin-scoped. An opt-out on www.example.com does not carry to shop.example.com. If you run one product across subdomains you must call optOut() on each origin yourself — a shared cookie at the registrable domain is not implemented.
