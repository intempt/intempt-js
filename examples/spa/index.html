Single-page app routing

The point of this example is how little code it takes: the SDK tracks SPA route changes on its own. It patches history.pushState and history.replaceState and listens for popstate, so each navigation emits a Leave Page for the old route and a View Page for the new one. The router below contains no analytics calls at all — every page event in the log came from the SDK.

Serve this with a static file server and navigate using the links, not the address bar: python3 -m http.server has no rewrite rule, so reloading on /pricing returns a 404.

Three things to know before you rely on this

  • Hash-only routers are not tracked. The SDK hooks the History API and popstate; it does not listen for hashchange. If your router navigates by assigning location.hash, no page view is emitted. Either move the router to pushState, or call track({ eventTitle: 'Route Changed', data: { path } }) yourself on each navigation.
  • A replaceState that does not change the URL still emits a Leave Page. Press the button above and watch: you get an exit event with no matching view. Routers that use replaceState to sync query parameters or scroll state will inflate your exit counts. Prefer pushState for real navigations and keep replaceState for genuine URL corrections.
  • Back/forward can log the exit twice. A popstate navigation currently produces two Leave Page events and one View Page. Deduplicate on the platform side if exit counts matter to you.

What you still call yourself

Route changes are automatic; identity is not. Call identify() once you know who the visitor is, and again after a full reload — a client-side route change keeps the profile, but a reload starts from what is in storage.
